# 2026-10-19完整代码修复

修复范围是FLASK-RRTConnect的Connect循环与原始碰撞几何。保留r2、R=I、
rho=1、论文动力学、BVP目标、8个逻辑lane和有限时间网格；无新增规划算法。

## 阶段A：Connect重复状态

range的BVP时间插值可能在NN度量下远离目标，旧Connect会不断选择同一个
父节点，重复生成相同新状态。现在在插入前检查整棵当前树的flat状态，
重复则返回Trapped，让外层继续采样。没有要求所有动力学扩展的距离单调下降。
主结果输出duplicate_rejections；已有目标仍正确返回Reached。

独立固定状态回归和14项启用CTest通过。原5个node_limit案例在保持旧球
几何的本机复跑中均成功：Wall23为63节点，Q2Bug29为54节点，Hole27/36/39
分别74/67/84节点，每次检测到1次重复。这不是新的Ubuntu计时基准。
阶段A完整源快照保存在flask_connect_stageA_20261019.zip，可用于独立对照。

## 阶段B：原始几何

原始模型外形现在参与实际碰撞，不再仅用于绘图：

| 机器人 | 外形来源及几何 |
| --- | --- |
| Unicycle | visual_model原始size，0.5×0.25米矩形，使用恢复后的heading |
| Quad2D | visual_model原始size，0.6×0.2米矩形，使用曲线加速度恢复的姿态 |
| Quad3D | 原始默认sphere，size[0]=0.25米半径 |

动力学仍来自dynobench.model。visual_model现为实际碰撞和绘图共享的原始
几何入口，原始文件与论文动力学文件均未改动。

原始盒障碍保留为AABB；二维本体采用四轴SAT，球采用最近点/球距离。
接触算碰撞，统一数值容差1e-10米。scalar和AVX2采用相同公式，AVX2仍为
两组double4处理8个逻辑采样点。批次内核不再另行使用旧球—球最终判断。

r2 Quad2D节点缺少加速度，不能假定水平姿态；节点仅用内接圆进行必要
拒绝，完整外形在曲线上恢复姿态后检查。零时长路径也检查已给物理姿态，
没有足够姿态信息时不以r2节点圆检查冒充完整矩形检查。
Unicycle节点提前按signed-speed区间筛查，物理限制没有放宽。

## 配置变化

原生场景必须提供dynobench.visual_model；删除旧的robot_radius和
sphere_cell_size，原生形状/尺寸完全从原始文件读取。保留这些旧字段会
明确报错，避免调参时误以为仍能用小圆代替原始本体。
非DynoBench积分链/数学示例仍可显式配置球半径robot_radius。

continuous_sphere_collision仅支持球机器人和球障碍；原始盒场景未实现
连续界，开启会明确拒绝，不会因球列表为空而授予虚假证书。
当前六场景继续使用step=.01、连续检查false。

root examples是基准profile（goal_bias=0、shortcut上限100、Uni正向）。
examples/review_20261019保存用户最新实验的独立配置：goal_bias=.15、
max_nodes=20000、shortcut_attempts=20000、Bugtrap全程倒车-.3、Wall正向.3。
两者均已接入原始几何；不要混用旧球几何实验的成功率与新结果。
configure_six.py只重置根六配置，不覆盖review_20261019目录。

## Ubuntu编译和与最新配置一致的运行

建议将完整源码包解压到新目录，避免混用旧配置和二进制。

```bash
sudo apt install -y build-essential cmake libeigen3-dev libyaml-cpp-dev \
    python3 python3-numpy python3-matplotlib python3-yaml
cmake -S . -B build-native1019 -DCMAKE_BUILD_TYPE=Release -DFLASK_ENABLE_AVX2=ON
cmake --build build-native1019 --parallel 2
ctest --test-dir build-native1019 --output-on-failure
/usr/bin/python3 -I -m unittest discover -s tests -p test_measurements.py -v

PROFILE_DIR=examples/review_20261019
SCENARIOS=(
  "$PROFILE_DIR/dynobench_uni_bugtrap.yaml"
  "$PROFILE_DIR/dynobench_uni_wall.yaml"
  "$PROFILE_DIR/dynobench_quad2d_bugtrap.yaml"
  "$PROFILE_DIR/dynobench_quad2d_hole.yaml"
  "$PROFILE_DIR/dynobench_quad3d_block.yaml"
  "$PROFILE_DIR/dynobench_quad3d_window.yaml"
)
RUN_DIR="results/native1019_$(date +%Y%m%d_%H%M%S)"
/usr/bin/python3 -I tools/benchmark.py \
  --executable build-native1019/flask_plan --scenarios "${SCENARIOS[@]}" \
  --output "$RUN_DIR" --seeds $(seq 20 39) --budget 10 --backend simd \
  --checkpoints .001 .005 .01 .05 .1 .5 1 5 10
/usr/bin/python3 -I tools/plot_six.py "$RUN_DIR" --seed 20 --at-budget .01 .1 1 10
xdg-open "$RUN_DIR/cost_time.png"
```

benchmark遇到规划失败可能返回2，但保留记录并完成统计；失败不填0。
绘图使用输入快照，不会将旧路径重新按新几何判作成功。
